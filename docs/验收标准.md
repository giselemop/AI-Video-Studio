# 验收标准

## 一、验收状态定义

- [ ] 未验收：尚未实际执行或证据不足。
- [~] 部分通过：有实现或局部证据，但仍有缺口、Mock、未接链路或未覆盖异常。
- [x] 已通过：已执行可复现测试，结果和范围有记录。
- [!] 验收失败：实际执行不符合条件，必须记录原因和修复。
- [?] 无法验证：缺少外部环境、模型、权限或用户决定，不能用推断替代。

代码存在、接口返回 200、文件存在或历史聊天描述都不能单独标记 [x]。

## 二、通用验收要求

- [x] 结果可以从命令、API、FFprobe、数据库查询、日志或人工检查复现。
- [x] 密码、Token、API Key、Cookie 不写入 Markdown、Git、日志和报告。
- [~] 修改不会覆盖用户未提交业务代码；本轮用户修改已保护，但未执行完整运行时回归。
- [ ] 关键失败、取消、超时、重试、恢复和边界条件均有回归。
- [~] 关键业务模块有正常、异常、边界、数据一致性、UI、API、数据库、权限和稳定性验收。
