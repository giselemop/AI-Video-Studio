## 一、架构概览

~~~~mermaid
flowchart LR
  UI[Vue 3 + Element Plus] --> Auth[本机管理员会话 + CSRF]
  Auth --> API[ASP.NET Core .NET 8 Minimal API]
  API --> DB[(MySQL 8 ai_video_studio)]
  API --> Q[GenerationQueue]
  Q --> C[ComfyUI HTTP API]
  Q --> F[FFmpeg / FFprobe]
  Q --> T[Windows System.Speech]
  C --> M[C:\install\AI\Models]
  API --> W[C:\install\AI\Workflows]
  API --> D[C:\install\AI\Data]
~~~~

当前 API 和 ComfyUI 默认只监听 127.0.0.1。系统适合本机单操作者受监督使用，不等于局域网或公网安全架构。

业务 API 默认要求本机 `Administrator` 会话；首次使用从本机登录页创建管理员账号，服务仅存 PBKDF2-SHA512 校验值。危险方法需同时通过 CSRF 和精确 Origin 校验，安全审计写入 MySQL。

## 二、技术栈

| 层 | 当前实现 |
| --- | --- |
| 后端 | .NET 8 ASP.NET Core Minimal API、C# |

| 前端 | Vue 3、Element Plus、Vite 6；单入口 App.vue，无 vue-router |

| 生成 | ComfyUI HTTP /prompt、/history、/view、/interrupt |
| 媒体 | FFmpeg/FFprobe；本地 Data 目录 |
| 音频 | Windows System.Speech TTS、SRT、SFX/BGM、FFmpeg 混音 |
| AI 解析 | 本地 RuleBased；可选 OpenAI-compatible/DeepSeek/OpenAI 适配器 |
| 操作系统 | Windows 11，Intel i5-13600KF、32GB、RTX 4070 12GB |
| 构建 | npm run build、dotnet build/publish、PowerShell/bat |

## 六、前后端关系

生产构建后的 web/dist 由 ASP.NET Core 静态文件中间件提供。开发模式 Vite 监听 127.0.0.1:18081，并把 /api 和 /media 代理到 18080。当前页面没有独立路由，刷新恢复和浏览器 E2E 仍是待建设项。

## 七、API 结构

- 基础：/api/health、/api/dashboard、/api/system/settings。
- 项目对象：/api/projects、/api/episodes、/api/characters、/api/scenes、/api/shots、/api/assets。
- 生产：/api/scripts、/api/production、/api/shots/{id}/prompt、/api/audio、/api/episodes/{id}/subtitles。
- 任务：/api/tasks、cancel、retry、rerun、A/B。
- 质量：/api/qa/technical-check、shots、episodes、review、unlock、export。
- 媒体：/api/media、角色/场景参考图上传、SFX/BGM 上传。

当前 API 无统一认证、权限、CSRF、requestId 和资产归属边界；这是 P0 风险，不是文档遗漏。

## 八、数据库结构

核心表分为项目/资产、生成配置、任务、剧本/Prompt、声音和 QA/审计。MySQL 保存状态、路径元数据、哈希、任务、结果、QA 和操作日志；二进制媒体和模型保存在磁盘。

当前 API 核验：2 个项目、2 个 Episode、17 个 Shot、2 个角色、7 个场景、32 个资产；任务 68 个，其中 63 个成功、3 个历史失败夹具、2 个取消。

初始化入口是 scripts/init_database.ps1，迁移前应执行 scripts/backup.ps1。备份可读性和隔离恢复本轮未验证。

## 九、缓存

音频有数据库音频缓存；任务执行有进程内 Channel/活动任务结构。当前没有 Redis、消息队列或分布式缓存。内存状态不能替代 MySQL 权威状态，分布式租约和幂等仍待实现。

## 十、文件系统

外部 Data 存放角色/场景参考图、生成结果、音频、字幕、QA、临时文件和 Release。Models 和 Workflows 不进 Git。当前多个代码路径直接传递文件路径，统一 PathPolicy、manifest、隔离目录和原子发布是 P0/P1。

## 十一、第三方服务

- ComfyUI：本地 HTTP 生成服务。
- FFmpeg/FFprobe：本地进程，负责媒体处理和质量检查。
- MySQL：本地数据库服务。
- OpenAI-compatible/DeepSeek/OpenAI：可选出站 LLM，当前不应在未完成 allowlist、超时、预算和密钥边界前配置外部地址。

## 十二、AI 服务

本地规则解析不依赖外部网络。配置 LLM 后 ScriptAnalyzer 可调用兼容 API；当前代码从数据库设置读取 BaseUrl/API Key，地址和秘密安全是待整改边界。ComfyUI 模型目录当前登记 3 个模型、0 个 LoRA、8 个工作流。

## 十三、认证与权限

当前无登录、会话、RBAC 或 CSRF；服务默认回环监听只降低暴露面，不构成认证。局域网/公网必须先完成 P0 认证、权限、TLS、限流、审计和数据库/ComfyUI 隔离。

## 十四、定时任务

没有独立 cron/Windows Scheduled Task 作为业务事实源。GenerationQueue 是宿主进程内 BackgroundService；服务重启会按现有逻辑处理遗留 Running 任务，但租约、心跳和多 worker 对账尚未验收。

## 十五、日志

FileLoggerProvider 写入 logs；生产、QA 和环境脚本写入 JSON/文本报告。当前需继续避免凭据进入日志，并补 requestId、actor、resource、错误分类和脱敏。

## 十六、异常处理

Program.cs 有全局异常中间件，MySQL 异常返回 503，其他异常返回 500。当前错误响应仍可能暴露异常消息，生产安全版本需要统一错误码和脱敏。

## 十七、部署架构

本机启动由 start.bat 负责检查并启动 ComfyUI、检查 MySQL、启动已发布 VideoStudio.Server.exe 并打开浏览器。停止使用 stop.bat；发布使用 scripts/publish.ps1。当前没有 IIS/Nginx/容器/远程 worker/公网上线架构。

## 十八、关键数据流

项目/Episode → 角色/场景 → 剧本 → Shot → Prompt → 关键帧 → I2V → Technical/Shot QA → FFmpeg 增强 → TTS/SRT/SFX/BGM → Episode QA → 人工 Approved/锁定 → Master/QA 报告。
