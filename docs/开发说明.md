# 开发说明

## 一、环境要求

- Windows 11 64 位。
- .NET 8 SDK/runtime。
- Node.js/npm，前端依赖已在 web/node_modules 中准备。
- MySQL 8，默认 127.0.0.1:3306。
- 现有 ComfyUI 和可用模型/工作流。
- C:\install\FFmpeg\bin\ffmpeg.exe 与 ffprobe.exe。
- 推荐硬件：Intel i5-13600KF、32GB RAM、RTX 4070 12GB；GPU 任务并发 1。

## 二、外部依赖

- C:\install\AI\ComfyUI：现有 ComfyUI，不复制进本仓库。
- C:\install\AI\Models：当前扫描 3 个模型；LoRA 当前为 0。
- C:\install\AI\Workflows：当前扫描 8 个 JSON 工作流。
- C:\install\AI\Data：项目、角色、场景、输出、QA 和临时文件。
- C:\install\FFmpeg：媒体处理。
- Windows PowerShell/System.Speech：可选本地 TTS。

## 三、数据库

数据库名：ai_video_studio。默认连接 127.0.0.1:3306。

密码只放在未跟踪的 config/local.env，不能写入 Markdown、源码、报告、日志、截图或 Git。新机器配置步骤：

    Copy-Item config/local.env.example config/local.env
    编辑 config/local.env，填写现有 MySQL 账号密码

数据库初始化/升级入口：

    powershell -NoProfile -ExecutionPolicy Bypass -File C:\install\AI\VideoStudio\scripts\init_database.ps1

脚本会在可用时先备份；迁移前不要删除数据库或业务数据。当前本轮未执行迁移。

## 四、配置文件

- config/appsettings.example.json：安全配置结构示例。
- config/config.example.json：参数结构示例，不是秘密文件。
- config/local.env.example：本机环境变量示例。
- config/local.env：未跟踪的本机秘密配置，不要复制到报告或提交。

关键配置名称：

- AI_VIDEO_STUDIO_DB_HOST
- AI_VIDEO_STUDIO_DB_PORT
- AI_VIDEO_STUDIO_DB_NAME
- AI_VIDEO_STUDIO_DB_USER
- AI_VIDEO_STUDIO_DB_PASSWORD

ComfyUI、Models、Workflows、Data、FFmpeg 路径应与本机实际目录一致。

## 五、后端启动

推荐使用仓库根目录 start.bat：

    C:\install\AI\VideoStudio\start.bat

它会检查/启动回环 ComfyUI、检查 MySQL、启动 server/publish/VideoStudio.Server.exe 并打开 http://127.0.0.1:18080。

停止：

    C:\install\AI\VideoStudio\stop.bat

启动后先检查：

    curl.exe http://127.0.0.1:18080/api/health
    curl.exe http://127.0.0.1:8188/system_stats

## 六、前端启动

开发模式：

    cd C:\install\AI\VideoStudio\web
    npm run dev

Vite 地址为 http://127.0.0.1:18081，并把 /api、/media 代理到 18080。生产模式由 ASP.NET Core 提供 web/dist，不必同时启动 Vite。

## 七、完整项目启动

1. 确认 MySQL、ComfyUI、模型、工作流和 FFmpeg 存在。
2. 确认 config/local.env 已配置但不输出密码。
3. 首次安装或 schema 变更前执行 scripts/backup.ps1，再执行 scripts/init_database.ps1。
4. 运行 start.bat。
5. 打开 127.0.0.1:18080，先看系统健康和任务是否有 Pending/Running。

## 八、编译与发布

后端：

    cd C:\install\AI\VideoStudio
    dotnet build server\VideoStudio.Server.csproj --no-restore --nologo

前端：

    cd C:\install\AI\VideoStudio\web
    npm run build

发布：

    cd C:\install\AI\VideoStudio
    powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\publish.ps1

发布前确认没有正在运行的旧 server/publish 进程锁定输出目录；不要覆盖用户未提交修改。

## 九、测试

静态检查：

    dotnet build server\VideoStudio.Server.csproj --no-restore --nologo
    cd web
    npm run build

非真实生成回归：

    powershell -NoProfile -ExecutionPolicy Bypass -File C:\install\AI\VideoStudio\scripts\test_production_pipeline.ps1

该命令验证 health、文件、数据库和 RuleBased 5 Shot 分析，不占用 GPU。只有明确需要真实生成时才使用：

    powershell -NoProfile -ExecutionPolicy Bypass -File C:\install\AI\VideoStudio\scripts\test_production_pipeline.ps1 -RunRealGeneration

QA 夹具：

    powershell -NoProfile -ExecutionPolicy Bypass -File C:\install\AI\VideoStudio\scripts\qa_test.ps1

环境探针：

    powershell -NoProfile -ExecutionPolicy Bypass -File C:\install\AI\VideoStudio\scripts\check_environment.ps1

测试结果必须分别写为已验证通过、验证失败、未执行和无法验证。不能把未执行的真实生成、浏览器、并发、安全或恢复测试写成通过。

## 十、发布

当前没有远程仓库、CI、tag、IIS/Nginx、容器或公网发布流程。当前可发布边界只有本机受监督研发。局域网/公网在认证、CSRF、路径安全、任务幂等、最小权限、TLS、审计和恢复验收前为 No-Go。

## 十一、部署

部署依赖本机外部目录和服务，不把模型、媒体和秘密打包进 Git。部署前确认：

- C:\install\AI\ComfyUI 只监听 127.0.0.1:8188。
- API 只监听 127.0.0.1:18080。
- MySQL 账号、端口和权限符合当前本机边界。
- C:\install\AI\Data 有足够磁盘空间；低于 50 GB 应告警，低于 20 GB 不应批量生成。
- 发布前已有数据库和文件备份，备份可读性尚未在本轮证明。

## 十二、常见问题

- 数据库离线：检查 MySQL 3306、config/local.env 和 scripts/init_database.ps1；不要重置机器上其他项目使用的 root 密码。
- ComfyUI 离线：检查 8188、ComfyUI 日志、模型和工作流文件；不要手工把任务改成成功。
- 显存不足：保持 GPU 并发 1，先降低帧数，再降低分辨率、候选数和 steps。
- FFmpeg 不可用：检查 C:\install\FFmpeg\bin\ffmpeg.exe 和 ffprobe.exe。
- TTS 不可用：检查 Windows PowerShell/System.Speech；TTS 不可用时不能伪造音频结果。
- 前端只显示空页：先运行 npm run build，确认 web/dist/index.html 存在，再重启 server。
- 发布文件被占用：安全停止现有 VideoStudio.Server.exe 后再发布，确认无 Running 任务。

## 十三、开发注意事项

- 不读取、打印或提交 config/local.env 的秘密。
- 不 reset、checkout、clean、删除或覆盖用户未提交修改。
- 不执行 DROP DATABASE、无确认 DROP TABLE、清库、批量删除业务媒体或直接改状态。
- 迁移/数据库修复前先备份并保留可追溯记录。
- 真实生成只使用实际模型/工作流；失败只回炉失败 Shot，自动回炉最多两次。
- 修改 UI 后必须执行真实浏览器操作；build 通过不等于 UI 验收通过。
- 任何重大数据库、框架、架构、模型或部署变化先在 docs/技术决策.md 新增决策。
- 每次重要任务结束都要检查 diff、编译、测试、验收、项目状态、待办、变更记录和 Git status。
