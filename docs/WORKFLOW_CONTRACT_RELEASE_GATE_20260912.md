## 2. 已落地的生产链路约束

### 阶段 A：工作流执行契约

新增 `config/workflow-contracts.json` 和 `server/WorkflowContracts.cs`。每条登记路线包含工作流 ID、版本文件名、SHA-256、任务类型、节点角色/节点 ID/输入名、模型文件及实际权重 SHA-256、显式输入槽位、尺寸/帧率/帧数、输出和许可状态。执行计划还记录实际解析路径、权重指纹和 ComfyUI/运行依赖指纹；权重哈希按文件大小和修改时间缓存，替换同名文件会被阻断；同名模型出现多个解析路径也会阻断，避免 ComfyUI 按文件名加载未登记权重。

视频任务必须显式声明 `WorkflowId` 或 `workflowVersion`，不会按模型可用性自动选路或静默回退。身份参考、首帧、引导帧、场景参考、姿态等通过 `inputSlots` 独立绑定；不再用 `LoadImage` 遍历顺序或通用旧字段猜测角色。必要槽位缺失、旧 `referenceImages/controlImages` 混用、资产路径越界、资产不归属当前项目、契约哈希/节点/模型不匹配，均在 GPU 前拒绝。

对工作流的请求参数、契约规范化后的执行参数、ComfyUI 执行图和输出探针分别留痕。自动 QA 重试、生产任务和前端提交复用同一契约检查，不得通过换 seed 绕过；重试默认继承原路线、动作、角色和输入槽位，只有与失败原因对应的参数才会变化。

### 阶段 B：帧数、尺寸与封装

已定位 LTX 73 帧变 81 帧的根因：LTX latent 节点按 `((length - 1) / 8) + 1` 建立 latent，解码端输出 `8 * latentLength + 1` 帧。因此请求输出 73 帧时，执行节点长度必须是 65，最终解码目标为 73；角色锁定路线的引导帧为 64。当前“73→65→73”是代码推导与夹具通过，等待新生成验证；请求帧数、执行帧数和输出帧数现在分开记录，不再用裁剪掩盖根因。

视频输出探针核对宽、高、帧数、帧率、时长、色彩和音轨；WEBP 转 MP4 时按契约帧率处理，并保留音频策略。原始输出和后期输出路径分开登记。720p 只作为交付规格，不把低分辨率源描述为原生 720p 细节；默认不插帧。

### 阶段 C/D：角色资产与动作来源

新增角色参考图查询和人工审核接口，并将审核接入生产准入：

- `GET /api/characters/{id}/references`
- `POST /api/characters/{id}/references/{referenceId}/review`

前端提供“审核参考图”入口，支持 Approved、Rejected、NeedReview、版本/资产对照和备注。审核人从已登录身份取得，审核历史追加写入；生成前和执行开始会重新核对 Approved、审核时资产版本及当前哈希，素材变化或撤回批准会把关联镜头置为 NeedReview，并解除已批准整集的锁定。自动相似度不能替代人工审核。没有可靠多角度资产时，镜头角度仍应限制在已审范围内；不能把独立生成的相似人物图直接认作同一角色。

动作控制与身份参考分离。当前可登记/路由的验证顺序为微表情、小角度转头、半身抬手；走路、坐下、拿杯子、开门、遮挡、对白和复杂互动仍需各自的控制素材、接触/遮挡要求和人工验收，不能由提示词单独宣称已支持。同一镜头自动定向重试最多两次，仍失败时转人工、换路线或阻断。

### 阶段 E：模型准入与路线状态

契约会核对实际模型解析路径、权重哈希和运行依赖指纹，并把实验/生产状态、许可状态和模型清单写入任务追踪；文件变化后需要重新验证。H3 仍是待验证候选：已有路线隔离和夹具回归，但没有在本轮完成真实 GPU 输出、完整许可证核验、销售/官方条款比对、正式内容审核或发布许可确认。开放权重不被自动当作无限制商用。

### 阶段 F：队列、后期和发布候选

GPU 重任务仍使用全局并发 1；任务、尝试、模型、输入槽位、输出、QA 和重试关系留存。新增 `ReleaseEligibilityService`、`ReleaseCandidateRepository` 和迁移 `009_release_candidate_packages.sql`，将以下状态分开记录：

- `TechnicalStatus`：文件、规格、音频、探针、镜头技术 QA。
- `ContentStatus`：身份、动作、连续性、画面缺陷和人工内容审核。
- `ReleaseEligibility`：许可证据、AI 标识、Episode/镜头审核、锁定状态和阻断问题。

新增接口：

- `GET /api/qa/episodes/{id}/release-eligibility`
- `GET /api/qa/episodes/{id}/release-candidates`
- `POST /api/qa/episodes/{id}/release-candidates`
- `POST /api/qa/episodes/{id}/export`

候选包只有在技术状态、人工内容状态、整片/镜头/字幕/音频/封面及审核版本快照、许可证证据、AI 标识和 Episode 锁定条件同时满足时才可进入 Ready。导出必须明确提交 `candidateId`，不会再从历史 Ready 候选中任意选取；排队、worker 开始和最终落盘分别核对候选版本、来源快照哈希和交付文件哈希，来源变化会使旧候选过期。候选版本分配使用幂等键与唯一键冲突重试。候选创建接口明确返回 `uploadPerformed=false` 和 `publicReleasePerformed=false`，本轮未执行外传。
