# Video Studio 质量验收说明

## 验收范围

验收状态只有 `Passed`、`Failed`、`Blocked`。`Failed` 必须记录原因并完成最小修复、重新测试和相关回归；只有同一外部阻塞连续三轮仍无法解决时才允许 `Blocked`。不能使用“Almost Passed”“基本可用”等状态。

质量验收不重新生成视频，也不加载大型视觉模型。它由 FFmpeg/FFprobe 和 CPU 采样完成技术检查；人物身份、动作语义、场景连续性、构图等当前无法可靠自动判断的项目，明确进入 `NeedReview`，由制作者确认。

### 1. 技术验收

- 文件存在、大小大于 16KB、FFprobe 可读、FFmpeg 全量解码无错误。
- 视频分辨率精确匹配 Episode 的输出尺寸，默认 1920×1080。
- FPS 与目标值误差不超过 1，默认 30 FPS。
- 单镜头时长误差不超过 10%。
- 编码为 H.264/H.265；黑帧比例低于 2%。
- 有对白或旁白时必须有音频和有效 UTF-8 SRT，字幕不得重叠、超出视频时长或乱码。
- 抽样检查黑帧、亮度、帧间突变；异常帧会保存到 `C:\install\AI\Data\QA\Frames`。

### 2. Shot 评分

| 项目 | 权重 |
| --- | ---: |
| Technical | 15% |
| Character | 15% |
| Motion | 15% |
| Temporal | 15% |
| Semantic | 15% |
| Visual | 10% |
| Composition | 5% |
| Scene | 5% |
| Audio/Subtitles | 5% |

90 分以上为优秀，达到预设通过线为 `Passed`，低于通过线但达到复核线为 `NeedReview`，低于 70 分为 `Rejected`。分辨率、FPS、时长、解码、黑帧、缺失必需音频/字幕等硬失败直接拒绝，不会被普通分数掩盖。

### 3. Episode 评分

`Shot 平均 60% + 连续性 15% + 音频 10% + 字幕 5% + 节奏 5% + 视觉一致性 5%`。

- Standard：Episode 85 分通过；Shot 80 分通过、70 分进入复核。
- Draft：Episode 75 分通过；适合中间版本。
- HighQuality：Episode 88 分通过；适合发布前检查。
- 只要有一个 `Rejected` 镜头，Episode 不能通过。
- 节奏异常只产生 Warning，不会单独自动拒绝。

## 自动重生成

技术硬失败或 Shot 低于 70 分时，如果存在选定关键帧/参考图，系统按 QA 任务中的原因重新提交 I2V；每个镜头最多自动重生成 2 次。超过上限后保留 `NeedReview`/`Rejected` 结果，必须人工决定，不会无限循环。

## 审核与发布锁

人工可以将 Shot 标记为 `Passed`、`Rejected` 或 `NeedReview`，也可以忽略普通 Warning。Episode 只有在全部镜头 `Passed` 且不存在未关闭的 Critical/Error 问题时才能 `Approved`。Approved 会锁定 Episode；修改前先解锁，重新 QA 后再导出。

## Master 导出

Approved 后点击“导出 Master”，文件写入：

`C:\install\AI\Data\Output\Release\项目名\Episode001`

包含：`*_MASTER.mp4`、SRT（若启用）、封面、`QA_REPORT.md`、`QA_REPORT.json`。导出前再次检查 Approved、镜头状态、关键问题和视频文件，避免把未验收版本当成成片。

## API 与测试

- `POST /api/qa/technical-check`：不依赖数据库的技术验收。
- `POST /api/qa/shots/{id}/check`：提交 ShotQA CPU 任务。
- `POST /api/qa/episodes/{id}/check`：提交 EpisodeQA CPU 任务。
- `POST /api/qa/shots/{id}/review`、`/api/qa/episodes/{id}/review`：人工审核。
- `POST /api/qa/episodes/{id}/export`：提交 Master 导出。

运行 `C:\install\AI\VideoStudio\qa_test.bat`，结果写入 `C:\install\AI\VideoStudio\logs\qa_test.log`；测试会覆盖正常、黑帧、短时长、错误分辨率、损坏尾部、缺音频和字幕超时场景。当前数据库凭据已配置，真实 Episode QA 已执行；最近一次 3-shot Episode 得分 91.11、Approved/locked、技术 QA 100。后续测试必须继续使用真实数据库、ComfyUI、FFprobe 和实际输出，不得 Mock QA 分数。
